# تحديث تجريبي لترحيل بلوساب متعدد القفزات

أضيفت في هذه المرحلة قائمة ترحيل دائمة في SharedPreferences، تُحفظ قبل محاولة الإرسال وتُستعاد بعد إعادة تشغيل التطبيق، مع إعادة محاولة كل 15 ثانية وحذف العناصر المنتهية الصلاحية. اكتشاف أجهزة الشبكة المحلية UDP الموجود في LocalNetworkService يستمر في تحديث قائمة النظراء كل 5 ثوانٍ.

## حدود مهمة
- هذه المرحلة لا تنفّذ بعد إقرار تسليم طرفي موثوق؛ نجاح كتابة المقبس لا يعني أن المستلم النهائي استلم الرسالة.
- لا تنشئ اتصال Bluetooth تلقائيًا مع كل جهاز مكتشف؛ اتصال RFCOMM والتزاوج/موافقة أندرويد قد يكونان مطلوبين.
- اكتشاف LAN يعمل فقط على الشبكة المحلية/نطاق البث نفسه، وليس بين شبكات Wi-Fi منفصلة.
- يجب عدم اعتبار فتح التطبيق ضمانًا لتشغيل Bluetooth أو Wi-Fi أو السماح بكل الصلاحيات.
- لم يُجرَ بناء Flutter أو اختبار فعلي على ثلاثة هواتف في هذه البيئة. يلزم اختبار على أجهزة حقيقية قبل الاستخدام الإنتاجي.

## خطة الإكمال
1. توحيد غلاف الرسالة: messageId, destinationId, originId, hopCount, expiresAt, path.
2. ACK منفصل لكل قفزة مع إعادة محاولة محدودة، وACK نهائي من الوجهة لإزالة الرسالة من الطابور.
3. اكتشاف Bluetooth وربط تلقائي ضمن قيود Android، مع إدارة الاتصالات المتزامنة وحدود البطارية.
4. اختبار A→B→C مع قطع/إعادة الاتصال، التكرار، إعادة التشغيل، وانتهاء الصلاحية.
