# البنية (1.1.0)

## الطبقات
```
الواجهات (lib/screens, lib/main.dart)
   │  تستمع إلى أحداث النقل وتعرض/تحفظ
خدمات التطبيق (lib/services)
   ├─ identity_service      هوية ومفاتيح الجهاز (Ed25519 + X25519)
   ├─ packet_security       توقيع/تحقق/تشفير/فك تشفير كل حزمة
   ├─ mesh_relay_service    ترحيل متعدد القفزات + تبادل القوائم
   ├─ delivery_service      إقرار التسليم (ACK) للمحادثات الخاصة
   ├─ message_store         رسائل في SQLite
   ├─ community_store       المجتمعات (SharedPreferences) + مفتاح المجتمع
   ├─ app_lock_service      قفل PIN مجزّأ
   ├─ background_service    الخدمة الخلفية (Foreground Service)
   └─ storage_ports         واجهات التخزين (لفصل المنطق عن الإضافات وللاختبار)
النقل
   ├─ bluetooth_classic_service  ←→ MainActivity.kt (RFCOMM)
   └─ local_network_service      UDP اكتشاف + TCP نقل
```
كل ما يخرج من الجهاز يمرّ بـ `PacketSecurity.seal`، وكل ما يصل يمرّ بـ `PacketSecurity.open` **داخل طبقة النقل**، فلا تصل حزمة غير موثّقة إلى أي شاشة.

## أحداث النقل (`BlousabEvent`)
| type | المعنى |
|---|---|
| `message` | حزمة سليمة ومقروءة؛ `message` = JSON بعد فك التشفير |
| `relay_only` | حزمة سليمة لا نملك مفتاحها (مجتمع آخر)؛ للترحيل فقط |
| `connected` / `disconnected` / `connectionError` | حالة اتصال بلوتوث |
| `lanPeer` | جهاز جديد ظهر على الشبكة المحلية |
| `lanStarted/Stopped/Error` | حالة الشبكة المحلية |

`rawMessage` يحمل الحزمة الموقّعة الأصلية ليمرّرها الوسيط كما هي.

## تدفق رسالة مجتمع
1. ChatScreen يبني JSON (`relay:true`, `hops:0`) ويرسله عبر النقل.
2. `seal`: يضيف `_pk,_xpk,_ts`، يشفّر `text/data/fileName/…` بمفتاح المجتمع، ثم يوقّع.
3. الجار يستقبل → `open` (توقيع، انتحال، تكرار، عمر) → فك التشفير إن كان عضوًا → حدث `message` أو `relay_only`.
4. `MeshRelayService` يقرر التمرير: عضو معتمد دائمًا، وغريب فقط إن فعّل «استخدام وسيط»؛ `hops<8`، `relayPath` بلا هذا الجهاز، عمر < 6 ساعات من `_ts`.
5. يُمرَّر لكل المتصلين عدا المصدر، ويُحفظ في الطابور. عند ظهور جهاز جديد: `mesh_have` ← `mesh_want` ← إرسال المطلوب فقط.

## تدفق رسالة خاصة
`seal` يشتق مفتاحًا من X25519 (مفتاح الطرف الآخر مخزّن من أول حزمة له) ويشفّر؛ المستلم يحفظ ويرد `ack` موقّعًا؛ `DeliveryService` عند المرسل يعلّم الرسالة ✓✓.
إن لم يُعرف مفتاح الطرف الآخر بعد، تُرسل موقّعة غير مشفّرة (تتحسن بعد أول تبادل hello).

| إدارة حالة (Riverpod/Bloc) | لم يُنفَّذ لنفس السبب |
| ترجمة النصوص (l10n) | لم يُنفَّذ |
| دخول بالبصمة | لم يُنفَّذ: يتطلب تغيير النشاط إلى FlutterFragmentActivity |

| ACK نهائي للمجتمعات | لم يُنفَّذ بقصد: يسبب عاصفة إقرارات؛ المعروض «أُرسلت» فقط |
